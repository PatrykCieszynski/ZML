# ZML Game Bridge - MVP Roadmap

Updated: 2026-08-09

This is the active MVP roadmap after real gameplay testing. Completed items were
removed from the main list so this file stays useful as a work queue.

Legend:
- `P0` - blocks trustworthy run tracking or app shutdown.
- `P1` - improves OCR/data reliability and reduces manual repair.
- `P2` - UI polish and operator ergonomics.
- `P3` - lower-risk cleanup.
- `Later` - after MVP or after more gameplay data.

---

## P0 - Correctness / Lifecycle

1. ~~**Electron/backend graceful lifecycle**~~
   - Done 2026-08-09.
   - Electron starts the local bridge in development and from bundled resources in production.
   - An already-running/custom backend is not adopted or terminated.
   - Unexpected exits use bounded automatic restart; app shutdown asks Uvicorn to exit through
     the parent pipe so FastAPI lifespan can stop workers and the SQLite writer.
   - Missing/lost Entropia window keeps OCR alive in `degraded` state and retries automatically.
   - Windows packaging produces one installer containing Electron and the Python bridge; `v*`
     tags publish it through GitHub Releases.

2. ~~**Merged finder/chat claim result**~~
   - Done 2026-06-02.
   - Chat deed confirmation can create a claim for a pending drop when finder OCR misses the result.
   - Finder hint remains the richer source for size/range/depth and updates the drop result separately.
   - Pending drop results are closed as no-resource by backend timeout.
   - Future multi-mode support still needs separate handling for multiple deeds from one drop.

3. ~~**Five-second durable drop lock**~~
   - Done 2026-08-09.
   - Duplicate `ProbeFiredSignal` observations inside the lock window do not create another
     `MiningDropEvent` or replace the pending drop.
   - Finder result, mode, and units signals remain active during the lock.

4. ~~**Separate TT and markup-adjusted drop cost**~~
   - Done 2026-08-09.
   - New drops persist `total_tt_mpec` and `total_with_markup_mpec` snapshots.
   - Dashboard, segments, and overlay show both totals; profit uses markup-adjusted cost.
   - Extractor keeps its existing single aggregated cost and is included equally in both run totals.

## P1 - OCR / Position Reliability

5. **Managed OCR Agent process split**
   - Contract foundation done 2026-08-09:
     - `packages/ocr-protocol` owns strict version 1 DTOs, NDJSON codec, and fixtures;
     - finder application signals no longer live under the OCR input implementation;
     - current OCR pipelines and startup behavior remain embedded and unchanged.
   - Embedded boundary done 2026-08-09:
     - `AppRuntime` starts and stops only the `OcrInputSource` port;
     - `EmbeddedOcrInputSource` wraps the current runner and converts positions at the boundary;
     - OCR remains in-process and finder signals keep using `RuntimeInputChannel`.
   - Standalone application done 2026-08-09:
     - `apps/ocr-agent` owns capture, pipelines, tests, native dependencies, and tessdata;
     - its runner emits protocol DTOs and has independent `--version`, `doctor`, and `stdio`
       entrypoints;
     - protocol mode emits `hello`, accepts `shutdown`, and the agent imports no Game Bridge code.
   - Managed subprocess done 2026-08-09:
     - `ZML_OCR_TRANSPORT=agent` selects a child process while `embedded` remains the default;
     - Game Bridge validates `hello`, drains stdout/stderr, monitors heartbeat, maps position and
       finder messages, and restarts failures with bounded exponential backoff;
     - worker health distinguishes process/restart failures from an unavailable capture window.
   - Config synchronization and process hardening done 2026-08-09:
     - Game Bridge sends a complete revisioned config after every `hello` and accepts observations
       only after the matching acknowledgement;
     - desired/applied revisions are visible in health and restart always performs a full resync;
     - deterministic child-process tests cover stderr pressure, malformed protocol, heartbeat
       timeout, unavailable capture, crash/restart, EOF, and forced shutdown escalation.
   - Independent Windows packaging done 2026-08-09:
     - Game Bridge and OCR Agent build as separate Python 3.13 PyInstaller artifacts;
     - Windows capture bindings, native OCR libraries, and tessdata exist only
       in the Agent artifact;
     - packaged Electron explicitly selects agent transport and passes the bundled Agent path;
     - CI verifies artifact ownership, protocol startup, config acknowledgement, and clean
       Bridge/Agent process-tree shutdown.
   - Next run packaged real-game smoke validation and an agent-mode gameplay soak.
   - Keep the embedded rollback transport until agent mode survives gameplay and packaged release
     validation.

6. **Runtime config and live settings**
   - Move operational OCR/runtime settings out of static env-only flows where practical.
   - UI should be able to read/update safe settings:
     - OCR intervals;
     - finder presence check;
     - drop result timeout;
     - drop circle TTL;
     - calibration profile/ROI;
     - selected debug capture options.
   - Apply low-risk settings live when possible.
   - For settings requiring worker restart, expose a clear restart/apply flow instead of silently waiting for full app restart.
   - Keep writes safe: config changes are not mining domain events and should not go through the SQLite event writer.

7. **Manual finder ROI calibration**
   - Current experiment: calibration tab captures a backend screenshot, user draws finder ROI, backend saves `screen_rois.finder`.
   - Keep this on a separate branch until UX feels good.
   - Prefer live reload or controlled OCR-worker restart after save.

8. **Manual compass ROI calibration**
   - Same direction as finder calibration, but for compass/position OCR.
   - Split Lon and Lat into separate ROI.
   - Support 5-digit and 6-digit coordinate presets if needed.

9. **Planet/location trust**
   - `/pos` chat waypoint is a trusted position input.
   - Done 2026-08-09: subsequent OCR positions with no planet inherit the latest trusted planet.
   - Lazy compass planet OCR remains a follow-up.
   - Use planet OCR mainly on large coordinate jumps or transition to unknown.
   - Future states: normal planet, `unknown`, `space`, `pvp_zone`.

10. **Compass latest-wins**
   - Deferred while synchronous position OCR keeps up with configured Hz.
   - If OCR becomes async/heavier: max pending job = 1, drop stale frames, latest result wins.

## P2 - UI / Operator Polish

11. **Debug tab rework**
   - Current debug view is still too close to a JSON wall.
   - Split into useful operational panels:
     - runtime/workers;
     - OCR/finder/position;
     - current run/segments;
     - latest durable events;
     - latest warnings.

12. **Calibration UX polish**
   - Once finder/compass calibration lands, make the tab comfortable:
     - show current saved ROI;
     - preview crop;
     - reset to default;
     - save profiles/presets.

13. ~~**Run and equipment utility actions**~~
   - Done 2026-08-09.
   - Loot view copies current-run aggregates as headerless, Excel-ready TSV.
   - Mining tool setup converts wiki PEC decay values to integer mPEC before creating a profile.

## P3 - Schema / Architecture Cleanup

14. **Mining claim projection cleanup**
   - Consider removing `position_z` / `depleted_z` from `mining_claims`; MVP map and matching are 2D.
   - Keep `range_m` in events as finder debug/context.
   - Do not promote `range_m` further unless UI or logic actually needs it.

15. **Event log scope and rebuild assumptions**
   - Event log is a recovery/debug journal, not the primary analytics table.
   - Critical rebuild facts should remain durable:
     - run/segment lifecycle;
     - drops;
     - hit/no-resource results;
     - claim created/depleted/ignored/expired;
     - equipment/setup changes.
   - High-volume observations should stay in projections/totals or transient signals.

16. **Docs handoff cleanup**
   - `docs/current-state.md` still lists some completed roadmap items as open.
   - Update it after the next meaningful architecture change lands.

## Later / After MVP

- Automatic planet switching from stable signals.
- History view for claims with date ranges.
- Full run/history export to CSV/JSON; active-run loot clipboard TSV is already available.
- Advanced classifier threshold editing after we collect enough data to know which knobs are safe for users.
